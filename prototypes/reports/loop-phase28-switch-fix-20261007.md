# Phase28 切换可靠性与卡顿修复（2026-10-07）

基线：远程 main / v0.1.214，91717ca。用户已验收当前候选并明确授权推送及发布；发布目标为 v0.1.215，验收后的产品代码保持不变，仅调整包版本元数据。

## 诊断与修复

1. **本机安装包架构与硬件不匹配。** `/Applications/Loop.app` 的 Electron 和鼠标辅助程序均为 x86_64，本机为 Apple Silicon。同一份真实任务结构、独立的新数据目录、相同测量方法下，已安装 Intel 版明显慢于 v0.1.214 的原生 arm64 打包版。已构建原生修复候选；正式安装文件仍保留。更新器依赖已有 Rosetta / arm64 检测和资源筛选，没有发现强制下载 Intel 的逻辑。仅凭这些结果不能断言所有 Intel 设备都慢，也尚未确定最初安装 Intel 版本的来源。
2. **重绘中断鼠标跟随。** 原 preload 在操作被认领后不再返回点击上下文；后续草稿/状态重绘误判为无点击，取消正在进行的跟随。修复后保持同一操作的上下文；未改变任务和页签且保留原操作元素时延续原动画，内容容器替换时接续原动画相位。任务或节点改变、元素消失及原有安全条件仍会终止跟随。
3. **工作台和编辑器反复重建。** 保留内容未改变的工作台及页签；按任务保留至多 8 个笔记编辑器，避免分组来回切换时反复初始化，同时保留编辑状态。保留的控件只绑定一次事件，避免重绘次数越多，事件处理越多。
4. **异步打开笔记的竞态。** 初始化未完成时容器被后续渲染替换，旧结果会被丢弃，却没有重试新容器。现会重试当前容器；外部重新加载会使旧初始化失效，避免旧内容覆盖新文档。
5. **输入路径上的保存开销及漏存风险。** 将完整数据比较移到合并后的自动保存中；跟随期间短暂让出主线程，退出/导出等显式保存仍立即执行。移除长度/时间戳签名作为持久化的跳过依据，确保相同长度的笔记和历史内容变化也能保存。
