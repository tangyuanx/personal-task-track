## 第 26 阶段：删除与恢复（最近删除）

以冻结的第 26 阶段基准（`loop-plane-phase26-candidate.html` + `loop-recovery-phase26.css/js` v1，全程未修改，三份文件 SHA256 与指令值一致）为唯一标准等效复现；Demo 的归档只存在页面内存、物以名称代替分组 ID，生产端改为真实存储、稳定 ID 与原子事务。

- **最近删除管理界面**：居中遮罩弹层（`min(880px,100vw-48px)` × `min(620px,100dvh-100px)`，圆角 12px，1024 紧凑档 `820px` + 左栏 290px），左侧 318px 记录列表（37px 选择头、69px 条目、单行省略 + 元信息）、右侧详情（26px/28px 内距，摘要保留换行与 135px 滚动）。搜索覆盖名称、原分组、所属任务；类型筛选覆盖任务、速记、分组、处理流节点、知识笔记。
- **单项操作固定在详情底部**：`恢复` / `恢复为副本`、可选`先查看所属任务`、`永久移除…` 位于独立固定操作区（最小 66px 高、16px/28px 内距、顶部分隔线），正文在其上方独立滚动——长笔记冲突时「恢复为副本」始终在首屏可见；其下是独立的底部批量栏（最小 57px 高、10px/20px 内距，左侧数量/保留说明、右侧永久移除或清空 + 恢复所选）。
- **两种选择状态互不影响**：点击条目只切换当前查看（`aria-pressed`），复选框才驱动批量选中；搜索与筛选不暗中丢弃已选项；全选只作用于当前结果，操作前按真实 ID 再核验对象。
- **统一归档、原子删改**：任务/速记（连同处理流、记录、简报、历史、笔记正文、属性、关联来源与排序位置）、整个节点子树（含所属任务、原父节点与原兄弟位置）、分组（保留内容或连内容一起）以及知识笔记正文，删除前先捕获当前富文本与节点记录草稿。所有删除入口接入同一服务：任务更多菜单、分组面板、批量删除、节点操作、笔记文件菜单（解除文件关联 / 移除软件内笔记）、知识笔记草稿对话框、设置 → 数据、空任务列表，以及今日浮窗的速记删除。
- **真实持久化**：归档是 `task-data.json` 中的一等集合（`recentlyDeletedSchemaVersion` + `recentlyDeleted[]`），删除与归档条目由同一次原子写入完成，写盘失败整体回滚、不显示成功；恢复同样先写活动对象再移除归档。降级保护覆盖新增的 schema 版本，旧版 Loop 不会覆盖新版归档；便携备份、校验备份、导入与旧目录恢复无需改动即已携带归档（含无归档键的旧备份兼容）。
- **恢复与冲突规则**：一律按稳定 ID 寻址，任何 ID 冲突都不覆盖、不静默合并；任务/速记恢复原分组与排序，分组丢失时默认未分组并可选目标；节点恢复先要有归属任务，任务缺失时禁用恢复并提供`先查看所属任务`，原父节点缺失时明确说明恢复到根层；分组重名要改名并内联报错；原始「保留内容」的归档只恢复组结构，12 秒撤销只把删除时迁走且此后未再变更的成员放回；笔记在所属任务存在且正文为空时恢复为草稿，否则「恢复为副本」在新任务中保留正文，不复制原任务的处理流、今日安排、截止/提醒/循环；恢复不补发旧提醒、不自动启动工作或增长。
- **永久移除独立确认**：说明范围、须勾选确认后才启用提交；只清除软件内的归档快照，不删除磁盘 Markdown、附件、活动对象或已有备份，也未新增任何自动清理或过期策略。
- **界面契约**：沿用第 22 阶段输入框与自定义下拉选项（键盘操作、类型筛选 136px、普通控件 34px）、第 24 阶段管理入口与第 25 阶段一体化标题栏；浅色/深色与字号设置、点外部关闭且不触发底层操作、Escape/Esc、Tab 约束、焦点返回与可访问名称全部保留。
