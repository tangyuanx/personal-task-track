## 第 27 阶段：界面切换性能与宽屏布局修复

本轮是性能与正确性修复，不新增用户可见功能，数据格式未变（`taskData` v2、`knowledgeSchemaVersion` 1、`recentlyDeletedSchemaVersion` 1），可直接覆盖升级。

### 切换性能（阶段 A–E）

- **未变更的知识笔记不再重复序列化**。此前每次切换都会对缓存中的隐藏编辑器做一次完整 Markdown 序列化，长笔记的成本会拖慢其后不相关的分组与导航操作。现在 `getMarkdown()` 以 ProseMirror 的文档对象为变更信号：文档未变直接返回缓存文本，只有真实文档变更才重新序列化；选区、聚焦与装饰更新不再触发。
- **渲染不再无条件安排整库写入**。`save()` 先用持久化状态指纹做快速判断，与已落盘内容一致时直接返回，不再构造并序列化整个任务数据；模型、分组、筛选等持久化字段变化时仍照常写入，保存与草稿安全语义未变。
- **浮窗快照按变更发布**。此前每次渲染都会重算今日任务、下一节点、分组与外观并发送；现在按输入签名去重，外观的 `getComputedStyle` 读取结果按主题/字体/字号缓存（实测该项由 2.9–4.7 ms 降至 0.005 ms）。
- **导航、顶栏与任务列表复用 DOM**。pane 切换不再重建这三块区域，列表滚动位置与逐行绑定得以保留；行级与控件级绑定改为幂等，避免复用后监听器叠加。
- **单次渲染只扫描一次筛选结果**，`blocked`/`later` 仅在对应筛选下才遍历节点树；编辑器挂载增加 pending 登记，防止同一次挂载在 Promise 完成前被重复创建。

### 修复

- **日历与回顾页面变形**：宽屏路由下任务列表槽为空会使网格多出一项，把 `1fr` 内容行挤到新轨道、第二行塌成 0，导航栏被压到 12px。现在宽屏时不输出该槽位。
- **日历右侧任务列表改为固定高度并可向下滚动**：此前列表按内容撑开（30 条当天任务实测 4861px，而窗口仅 820px），折叠以下的任务无法查看。现在列表在固定高度内滚动，内容高 4698px、可见高 609px。
- **日历/回顾等 toggle 按钮"点了没反应"**：`[data-action]` 的直接绑定缺少幂等保护，区域复用后与全局委托叠加，一次点击执行两遍 `action`，对 toggle 类操作互相抵消。已补 `actionClickBound` 等绑定标记，点击恢复为单次执行。

### 界面契约

`shell.css` 与 `index.html` 的样式表顺序均为冻结基线，本轮未改动：日历列表列的高度与滚动规则改由渲染器在加载时注入，`shell.css` 保持与冻结 Demo 字节一致，`index.html` 保持 Demo 的样式表加载顺序。冻结层集合继续逐字节校验。

### 验证

- `npm run check` 全绿：桌面 237 项 + 服务 11 项，0 失败；`git diff --check` 干净。
- 独立回归（真实 Electron、隔离数据目录、合成数据）：
  - 草稿安全：编辑后立即切走、退出重启后草稿完整；无编辑的纯导航 0 次完整序列化（16 次缓存命中）。
  - 区域复用：pane 切换后导航/顶栏/列表均复用，列表滚动位置保持，逐行绑定标记各恰好 1 个，任务集变化时列表正确重建。
  - 保存去重：纯导航不产生 task-data 写入，模型与分组变化仍落盘。
  - 浮窗实时性：真实变更后浮窗内容更新，no-op 渲染 0 次发布尝试。
- 规模与场景：200 任务 / 10 分组 / 每任务 12 节点 / 600 小节长笔记。今日↔完整仓库 38.7ms → 11.6ms（p50），选择任务 35.8ms → 24.9ms，分组切换 7.6ms（p50）/ 23ms（p95），处理流↔知识笔记 102.7ms → 89.1ms，切换路径完整序列化次数 20 → 0。
- 日历列表列：30 条当天任务下列表可见高 609px、内容高 4698px，可向下滚动；四路由（任务/日历/回顾/切回）导航、按钮与工作区尺寸一致，无横向滚动。

### 已知限制

- 长笔记首次挂载仍需解析整篇文档（600 小节实测约需数秒），本轮未改动该路径；笔记打开状态下的整页重建仍是主要成本。
- 阶段 D 中"合并多次滚动恢复"一项在实测后回退：那几次调用承载着现有语义（同视图保持偏移、换分组或筛选重置），且实测仅 0.075 ms/每次渲染。
- 阶段 E 的列表虚拟化未实施：200 任务下尚未触及合理帧预算。
- 性能数字来自本机 macOS（M 系列）单一环境，未在 Windows、DPI≠1 或 120Hz 下复测；800 任务规模本轮未复测。
